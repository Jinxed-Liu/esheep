# 牧场事实查询

先确定指标、时间、筛选、分组与对象。直接明细或单表聚合用 `query_farm_data` 并指定 `query_kind`；相邻记录、差值、时间间隔和变化率用 `calculate_farm_data` 的类型化算子计划。App 的 `FarmDataQuerySkill.swift`、查询引擎及工具契约负责校验与执行；不要按自然语言别名新增字符串路由。

## 不可混淆的口径

- `current_herd` 是 App 统一状态投影中的当前在群羊只，排除历史归档；不能仅凭“没有离群事件”判断在场。
- `born_lambs` 合计产羔事件 `lambCount`；`lambing_events` 统计产羔事件条数；`sheep_profiles.birthAt` 只是档案出生日期。三者不能互代。
- `born_lamb_lifecycle` 将产羔事件的出生总数与有出生日期档案的当前在群、死亡、出售、淘汰、转出分列。两套来源无法保证逐只对应，不能直接相减。
- 默认增重与 App 增重分析页复用 `WeightGainAnalyticsEngine`，用 `sample_policy=canonical_timeline`、`cohort=all_profiles`、`pen_membership=at_cutoff`。统一体重时间线包括可追溯称重、断奶重、初生重，同羊同日常规称重优先、同来源取当天最后一次。
- 圈舍按分析结束日牧场时区日末还原，当天截止到本轮事实读取时间。`pen_names` 一次传入全部精确舍名，单舍兼容 `pen_name`，不筛选时两者均空。按期末名单跟踪同羊，跨舍有效区间参与增重，保留逐次转群发生日期、原舍、目标舍及末次称重之后的转群。不能用当前圈舍或末次称重圈舍代替期末圈舍，不能把跨舍增重称为某舍独立贡献。
- 明确要求历史“在舍期间表现”才用 `pen_membership=at_measurement`；明确只用常规称重可选 `recorded_only`。这一独立口径在完整时间线上验证区间连续居舍，不能删掉中间样本再拼区间。批次核查全过程连续且唯一，跨越、重叠、退出重入和缺失须单列。负增重和零增重保留。
- 群体变化率即使包含多舍或日期范围，也用 `analysis_scope=complete` 和同羊真实相邻区间；明确要求单一值或单一分组才用 `focused`。返回总体、区间、批次、截止时点生命周期及数据完整性，多舍另逐舍报告，空舍显示 0 只、日增重 —。先汇总每羊有效区间增重与观察天数，再逐羊等权平均；区间等权和首末平均只作标明口径的补充。
- `date_from`/`date_to` 接受 `YYYY-MM-DD`（牧场时区完整日）或 ISO 8601，`as_of` 缺省按分析结束日截止，无结束日则用本轮事实时间。App 默认增重口径的显式 `as_of` 也以分析结束日封顶，更早的截止时刻同步收窄结束边界；期末名单与生命周期采用同一时点。区间两端均在所选范围，不借范围外称重点、不插值。当前仍在群子样本只在用户明确要求时用 `cohort=current_in_herd`。

## 回答边界

所有条件都须由工具实际执行；不能执行时说明缺口或拒绝近似结果。日期和月份使用牧场保存的 IANA 时区。报告数据来源、口径、样本及未知数；本地数据不代表云端已同步。把工具证据转成针对原问题的直接答案，不原样转述工具输出。
