## 安全边界

eSheepNext 使用 SwiftData 作为每台设备的离线工作库，通过独立同步层连接 CloudKit private/shared database。CloudBase Auth 与 CloudBase identity gateway 是唯一生产身份和协作权威，只保存账号、设备公钥、牧场目录的不透明 ID、成员角色、邀请、能力证书和删除审计，不保存牧场名称、羊只、圈舍、投喂、健康、繁殖、照片或统计。

CKShare 的 `readWrite` 权限只能控制参与者是否可读写共享记录，不能表达 eSheepNext 内部的字段级角色矩阵。管理员和员工在 CloudKit 层面均可能具备直接写记录的能力。因此，能力证书、设备签名、冲突隔离和异常硬删除检测是风险缓解与审计机制，不是不可绕过的服务端字段级权限。场主恢复区提供第二份加密照片与最近三份结构化 checkpoint，但只有完成真实 Development 恢复演练后才能把它视为已验证的灾难恢复能力。

如果未来需要严格的服务端字段级授权，必须将业务写入改为由受信任服务代理，成员不能继续直接写 CKShare。该方案会增加持续服务器费用，不属于当前锁定架构。

## 身份和会话

- App 为每次 Apple 登录生成 32 字节 nonce，并把 SHA-256 值传给 Apple。
- CloudBase Gateway 验证 Apple JWS 签名、算法、issuer、audience、签发时间、过期时间和 nonce。
- Apple identity token 指纹只能使用一次，重放请求会被拒绝并写入安全审计。
- authorization code 在 Gateway 与 Apple 交换 refresh token；refresh token 使用 AES-256-GCM 加密后保存。
- Gateway 通过 CloudBase 自定义登录签发 CloudBase 会话；刷新、退出与删除全部进入 CloudBase，不依赖 Cloudflare/D1。
- App 的 Access Token、Refresh Token 和原始 Apple user identifier 只保存在 Keychain。

## 设备和能力证书

- 每台设备生成独立 P-256 签名密钥，真机优先使用 Secure Enclave；不支持 Secure Enclave 的测试环境使用 Keychain 中的软件密钥。
- CloudBase 只保存设备公钥，不接收设备私钥。
- 能力证书由 Gateway 的 P-256 私钥签名，有效期七天，包含账号、牧场、角色、能力、设备 ID、签发时间和过期时间。
- App 每次上传前用设备私钥签名规范化操作数据。
- 下载端先验证能力证书，再验证牧场、账号和设备范围、payload SHA-256、所需能力和设备签名。缺少证书公钥或设备公钥时，操作进入隔离区，不覆盖本地数据。

## CloudKit 写入规则

- 每个牧场使用 `Farm_<farmUUID>` 自定义共享 Zone，通过 `CKShare(recordZoneID:)` 创建系统固定 Record ID 的 Zone-wide Share；场主另有不共享的 `FarmRecovery_<farmUUID>`。
- `operationID` 和业务实体 UUID 永久稳定，重复回调和重新发送必须幂等。
- 权威实体删除统一生成签名 `FarmOperation` 与稳定 `FarmTombstone`；出售、死亡和离场仍使用 `RemovalRecord`，不混用删除命令。恢复删除生成更高 revision 的恢复操作，不移除旧 Tombstone。
- 没有对应 Tombstone 的 `FarmEntity` 删除被记录为 `unexpectedHardDelete`，本地实体不会随之删除。
- 派生数据不上传，包括 `DailyPenCount`、羊天、搜索索引、天气缓存、Widget 快照、页面状态、迁移会话和迁移审计。

## 邀请和撤权

- 邀请码为八位大写字母与数字，排除 `0`、`1`、`I`、`O`，单次使用，24 小时过期。
- 同一账号 15 分钟内连续五次兑换失败会被锁定。
- 加入必须同时完成定向 CKShare 接受、邀请码兑换和场主参与者确认。
- 撤权时 CloudBase Gateway 立即撤销能力证书，场主还必须从 CKShare 移除参与者。被撤权设备的未确认 Outbox 只能导出，不得自动写入其他牧场。

## 照片与恢复

- 云端照片最长边 2560 像素，优先 HEIC 0.82，失败时 JPEG 0.86；重新编码会修正方向并去掉 GPS 与非必要 EXIF。
- `sourceDigest` 用于识别重复导入，`payloadDigest` 用于上传下载校验；相同压缩摘要不重复上传。
- 场主恢复区按压缩摘要保存 AES-GCM 加密副本，checkpoint 只引用照片，不重复复制二进制。
- 每牧场 256 位恢复密钥使用可同步 iCloud Keychain 保存；导出恢复包时生成一次性显示的 160 位随机恢复码，经 HKDF-SHA256 派生包装密钥。
- checkpoint 包含权威实体快照、逐类数量与摘要、Tombstone、照片引用、operation watermark 和成员 generation。恢复时先验证摘要与牧场编号，再按依赖顺序重放并生成新的 `recoverEntity` Outbox 操作。

## 成员快照与激活

- CloudBase 的 `security_generation` 只在成员确认、角色变化、成员撤权和设备撤销等真实安全状态变化时递增。
- 场主把 CloudBase 安全快照签名后写入 `FarmMembershipSnapshot`；较低 generation 会按回滚攻击拒绝。
- shared database 成员必须同时具备：已接受 CKShare、CloudBase active 成员、已验证且不低于 CloudBase generation 的场主快照、快照中登记的设备、当前有效能力证书。缺一项保持只读 `requiresAccountReview`。

## 当前阶段限制

- 云准入由服务层 `CloudAdmissionPolicy` 执行：Development 只允许具备已验证迁移提交和完整云端基线的正式迁移牧场；固定种子测试牧场、测试数据生成器及其模型标记已经删除。
- `isLocalOnlyMigration` 仅作为旧数据库兼容限制保留。升级服务只有在场主一致、迁移提交完整、引用与摘要重新校验通过并生成确定性基线后，才能在同一事务中解除限制；失败时保持本机可用且禁止创建 Zone、上传或共享。
- Production 代码路径已经与 Development 隔离，但在完成 Staging 双账号验收和 Production Schema 部署前不得上传真实生产牧场。
- 两个真实 iCloud 账户、两台设备和连续七天运行属于外部验收，不能由无签名构建或单元测试替代。
- `FarmAsset`、私有恢复资产、checkpoint、成员快照、签名 Tombstone 和冲突解决已经进入代码与自动化测试，但尚未取得双账号 CloudKit Development 和连续七日的端到端证据。
- CKSyncEngine state 损坏后的 staging Store 全量重拉与原子替换仍需在真实 CloudKit 数据上完成破坏性演练；在该验收之前，不能把重新安装或数据库损坏恢复描述为正式通过。
