# 繁殖周期关联与羊只详情 V18

## 业务边界

`ReproductionCycleResolver` 是 App 当前孕检、胎次和周期的唯一推导入口；Web 使用 `reproductionCycles.js`，两端执行同一组 `reproduction-cycle-cases.json`。孕检状态由事实推导，不单独保存怀孕开关。已完成产羔胎次与产羔记录数不同，流产结束妊娠周期但不增加产羔胎次。

初始周期用母羊 ID，后续周期用上一条产羔／流产记录 ID；高胎次确认表明缺失最近产羔时，仅以确认时间收窄可靠事实窗口，不构造周期结束事实，也不改变周期标识。配种轮次独立于胎次数字；补配沿用原轮次，新一轮配种生成新轮次。修正配种保留轮次根标识；修正日期使原孕检不再有效时进入待核实。相同发生时刻不使用 ID 排序确定业务先后。

新建或 Excel 建档的胎次空白仍为 0。历史档案无胎次依据继续待核实，不在迁移或页面读取时补造事实。历史模糊关联可保留为待核实；交互录入存在多个轮次时必须选择关联。旧格式修正未提供周期字段时保留已有明确关联；新格式明确提供周期时可通过审计修正解除关联。

## 兼容与发布顺序

1. 先应用 `20261017013000_reproduction_checkpoint_capability.sql`，保留现有发布暂停、保留和权限控制，再发布 `esheep-cloud-v2-writes` 对关联字段的读取、结构验证和 `capabilities` 响应，确认 `reproduction_contract_version >= 1`。
2. 部署能读取新增可空字段的 Web 投影与原生客户端。检查点含新关联字段时标为能力版本 2，旧数据仍为版本 1。旧事件、旧模板和字段缺失的旧检查点可继续读取；检查点新增字段为 nil 时不改变原始业务摘要。
3. 原生 V17 使用冻结模型，经显式轻量迁移到 V18。新增三个字段可空，不修改原始发生时间、孕检结果或审计记录。
4. 新格式写入前客户端检查云端能力。能力不足时保留草稿／待同步命令并提示服务更新，不能把本地保存显示为云端已接受。
5. 云端上线后按现有发布门禁执行真实账户同步与重新下载读回，分别核对审计回执、业务投影、App/Web 页面及通知。正式 TestFlight、生产 Web 和外部测试发布单独执行。

本改造没有业务表字段变更，但需要检查点发布函数的兼容迁移；不需要对生产数据库执行 reset。当前源代码实现并不表示上述服务已发布。

## 增重与显示

详情复用统一有效体重时间线，使用牧场时区、常规称重优先及同来源当天最后一次。完整时间线先建立相邻区间，之后筛选两端均在所选范围的区间。范围平均是总增重除以总观察天数，保留零和负值，未提前舍入。图表共用时间轴，选择显示起止日期、体重、天数、总增重、日增重和来源。

育肥期只从最近可确认的用途变更起算，档案直接写着“育肥羊”不能代替育肥开始事实。跨舍区间不能归因为某舍独立贡献。未设置牧场称重周期时只报告距上次称重天数，不判定逾期。
