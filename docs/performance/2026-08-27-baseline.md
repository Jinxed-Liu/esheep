首次完整运行在执行任何 XCTest 方法前崩溃，调用链为
`AppBootstrapController.prepareStore → CloudCollaborationStore.init → CloudSyncActor.init → CKContainer.init`。
Release 已关闭 CloudKit，但同步、照片、恢复点、成员快照、删除证据和重建 Actor
仍会在启动时创建 CloudKit 容器。`42abf75` 将这些资源延迟到真实 CloudKit 操作，
同时保留原容器标识、private/shared 引擎、状态序列化、启动修复和 authority 路径。
本地恢复测试新增了“操作前后均未初始化 CloudKit runtime”的断言。

完整验证采用两阶段串行流程：先 `build-for-testing`，再
`test-without-building`，关闭并行测试 worker，但保留 Debug 原配置和正常模拟器
签名。直接 `xcodebuild test` 在当前 beta 工具链曾停在 worker materialization；
`CODE_SIGNING_ALLOWED=NO` 又会使 Keychain 测试返回 `-34018`。验证脚本现已固化
前述两阶段流程，稳定 Xcode 门禁仍要求 0 失败、0 跳过。

## 采样协议

所有 signpost 只记录操作类型、记录数量和耗时，不记录耳号、账号 ID、牧场名、
用户 ID、图片内容或其他原始业务数据。Debug 默认启用；Internal TestFlight 通过
启动参数 `-EnablePerformanceTrace` 显式启用，不接入新的生产遥测服务器。

在同一台真实 iPhone、同一 Release 配置、同一牧场数据上执行：冷启动 10 次，
高频交互至少 30 次；同时使用真实数据原地采样，以及隔离测试容器中的 1 倍、
5 倍、10 倍匿名 fixture。真实数据不得导出。
