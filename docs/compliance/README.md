# eSheep+ 3.1 个人信息保护合规包

更新日期：2026-08-27  
拟生效版本：2026.09.01

本目录把 App 内告知、公开隐私政策、权限说明、第三方清单、出境告知、
App Store 隐私问卷、合规审计和影响评估统一到同一套真实数据流。它不是为了
把条款写得很长，而是确保每一项处理活动都能回答：处理什么、为什么处理、
由谁处理、保存多久，以及用户如何行使权利。

## 发布前必须替换和核验的信息

以下占位符未替换前，任何网页、App Store 元数据或正式隐私政策都不得发布：

| 占位符 | 必须填写的真实信息 |
| --- | --- |
| `{{LEGAL_ENTITY}}` | 运营者本人姓名或依法登记的主体全称 |
| `{{REGISTERED_ADDRESS}}` | 与运营主体一致、可用于法定联系的注册地址 |
| `{{PRIVACY_OWNER}}` | 实际负责处理权利请求、事件和审计的联系人 |
| `{{PRIVACY_EMAIL}}` | 可长期收件并能处理查阅、复制、更正、删除、撤回同意和投诉的邮箱 |
| `{{DOMAIN}}` | 已购买、启用 HTTPS 且由运营者控制的正式域名 |
| `{{SUPABASE_REGION_COUNTRY}}` | Production Supabase 控制台显示的实际国家/地区 |
| `{{SMTP_PROVIDER}}` | Production Supabase Auth 实际使用的邮件发送服务商全称 |
| `{{SMTP_REGION_COUNTRY}}` | SMTP 处理和存储邮箱/投递日志的国家或地区 |
| `{{SMTP_PRIVACY_URL}}` | SMTP 服务商的正式隐私政策或权利渠道 |
| `{{SMTP_RETENTION}}` | SMTP 邮件正文、投递状态和日志的实际保存期限 |
| `{{MIMO_API_REGION_COUNTRY}}` | MiMo 书面确认的当前 API 内容处理/存储国家或地区 |

运营者名称、联系方式、Supabase Production 项目区域、SMTP 服务商、日志和
备份保留周期以及 MiMo API 实际地域必须以线上控制台或服务商书面证据为准，
不能只凭仓库模板宣称完成。

## 已核实的生产边界

| 链路 | 当前代码事实 | 对外表述边界 |
| --- | --- | --- |
| 账号与新建云端牧场 | Supabase Auth、Postgres、Storage、Realtime；客户端使用 publishable key，数据库依靠 RLS 和 RPC 授权 | 当前计划选择新加坡，但必须按 Production 控制台实际区域填写并留存截图；未确认时不得声称服务已上线 |
| 旧牧场 | CloudKit 只用于读取、恢复和逐牧场迁移旧数据 | 不把 CloudKit 写成 3.1 新建牧场的权威数据库 |
| Apple 系统服务 | 通过 Apple 登录、MapKit、WeatherKit、CloudKit、APNs，以及本机日历、提醒、通知和生物认证 | Apple 自行处理的数据遵循 Apple 规则；本机权限不等于 eSheep 收集数据 |
| AI 助手 | 用户自带 MiMo Key，iPhone 直接请求 MiMo；会发送文字、经处理图片、语音和经用户逐次授权的牧场查询结果 | AI 为可选功能，必须单独同意；不能说“数据从不离开设备” |
| AI 个人空间 | Production 未配置 `IDENTITY_WORKER_URL` 时只保存在本机；旧身份网关配置存在时可同步端到端密文 | 仅在界面实际显示已启用时说明密文同步，不把未上线的旧网关列为当前生产受托方 |
| 广告与跟踪 | 未集成广告网络或跨 App 跟踪 SDK | 可声明不投放第三方广告、不出售个人信息、不进行跨 App/网站跟踪 |
| 诊断 | App 未集成第三方崩溃分析；新增性能跟踪仅在本机时不属于云端收集 | Supabase、MiMo 和 Apple 仍可能为安全与服务运行记录 IP、请求时间和技术日志 |

## 适用规则和维护节奏

本包按《中华人民共和国个人信息保护法》及 2026 年 9 月 1 日施行的
《小型个人信息处理者个人信息保护简化措施规定》编制。只有当前处理个人信息涉及的
自然人少于 10 万人时，才能按“小型个人信息处理者”管理；达到阈值、处理规模
显著扩大、发生重大安全事件或业务模式发生重大变化时，应立即重新判断适用规则。

- 每季度检查数据清单、第三方、权限、日志和删除任务。
- 每次发版检查 App、官网、Privacy Manifest 和 App Store 问卷一致性。
- 至少每五年按官方表格完成一次合规审计；发生重大变化或事件时提前审计。
- 每年复核 Production 区域、RLS/权限、备份、日志、MFA、域名和收件邮箱。

本材料是基于当前代码和公开规则形成的工程化合规底稿，不是律师出具的法律
意见。运营者仍应对线上配置、实际运营和填报真实性负责。
