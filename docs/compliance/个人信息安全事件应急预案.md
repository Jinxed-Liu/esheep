版本：2026.09.01

## 一、适用事件

包括但不限于：账号或生产后台被接管；Supabase/SMTP/MiMo/Apple 服务安全通知；
service role key、数据库密码、API Key 或恢复码泄露；RLS/Storage 越权；错误
牧场共享；导出/备份遗失；照片、位置、语音或业务内容被未经授权查阅、复制、
篡改、删除、丢失；恶意代码；账号删除失效；日志包含不应记录的个人信息。

普通同步失败、界面崩溃不当然属于个人信息事件，但如果导致越权、泄露、篡改、
丢失或不可恢复，应按本预案处理。

## 二、分级

| 级别 | 判断示例 | 响应 |
| --- | --- | --- |
| I 级重大 | 大量账号/牧场、精确位置、凭据或完整备份外泄；生产管理员失控；持续越权；可能造成重大损害 | 立即停止相关处理，最高优先级协调服务商，依法向网信等主管部门报告并通知个人 |
| II 级较大 | 单一或少量牧场数据被无权成员访问、可用凭据短时暴露、删除失败且存在继续访问可能 | 立即止损，2 小时内完成初评，依法决定报告/通知 |
| III 级一般 | 未实际访问的扫描、被控制措施拦截的误配置、仅去标识或低风险信息 | 修复、留证和趋势复盘；风险变化时升级 |

事件等级可随证据变化升级，不能因为当前只有一名用户就降低凭据和完整备份事件
的严重性。

## 三、发现后的动作顺序

### 0—15 分钟：确认和止损

1. 记录发现时间、来源、现象和当前操作者，不修改原始证据。
2. 撤销可疑会话、设备、成员或管理员；轮换泄露的 Secret/Key；关闭受影响
   Edge Function、API、Storage policy、Realtime 或邮件通道。
3. 必要时将 App/服务切到只读、关闭新注册或暂停 AI/出境传输。
4. 禁止用删除日志、覆盖数据库或重置整个仓库等方式“快速清理”证据。

### 15 分钟—2 小时：范围和风险初评

- 识别系统、环境、账号、牧场、字段、时间段、接收方和可能受影响人数。
- 判断是否包含邮箱、凭据、精确位置、照片、语音、自由文本、未成年人信息或
  完整业务备份。
- 核对数据是否加密/去标识、密钥是否同时泄露、是否已被下载/传播、是否仍可访问。
- 联系 Supabase、SMTP、Apple、MiMo 或其他相关方获取事件编号和处置承诺。
- 保存审计日志、请求 ID、数据库/Storage 元数据、配置差异和相关版本哈希；只
  在隔离位置保存必要副本。

### 2—24 小时：修复、报告和通知准备

- 修复根因并通过跨账号/跨牧场、拒绝路径、删除和回归测试验证。
- 评估已经采取的措施能否有效避免危害；不能避免时，依法及时通知相关个人。
- 依法需要向履行个人信息保护职责的部门报告时，不等待所有技术细节完美后才报告；
  先提交已知事实，后续补充。
- 准备用户通知和客服问答，不使用模糊的“系统升级”掩盖真实事件。

## 四、报告/通知内容

至少包括：

- 事件发生或可能发生的个人信息种类、原因、时间和范围；
- 已造成或可能造成的危害；
- 已采取和准备采取的补救措施；
- 个人可以采取的减轻危害措施，例如退出会话、改密、撤销 Key、核对成员；
- 运营者联系方式 `{{PRIVACY_EMAIL}}`；
- 尚不确定的事项和下一次更新安排。

如果采取措施能够有效避免危害发生，法律允许时可不通知个人；主管部门认为可能
造成危害并要求通知的，应当通知。所有判断必须有书面风险依据。

## 五、典型事件处置清单

### Supabase service role 或数据库凭据泄露

- 立即轮换凭据并检查所有 Edge Function、CI、本机配置和历史日志。
- 查询 Auth、API、Database、Storage、Edge Function 日志和异常导出。
- 检查 RLS/grants 是否被修改、是否新增用户/Owner、是否访问跨牧场对象。
- 旧凭据完全失效后再恢复写入。

### RLS、Storage 或成员越权

- 暂停受影响表/bucket/API 的访问；保存失败与成功请求证据。
- 修复 migration，并补充 anon/authenticated、跨账号、跨牧场、已撤权、离线写回
  的 allow/deny 测试。
- 确认 CDN/缓存/下载 URL 是否仍可访问并失效。

### 用户 API Key / AI 内容泄露

- 提醒用户在 MiMo 控制台撤销/轮换 Key；删除 eSheep 本机和可选密文副本。
- 确认 Key 是否进入日志、截图、崩溃报告或导出；逐处清理并轮换。
- 联系 MiMo 查询异常调用和额度消耗。

### 设备、导出或备份遗失

- 撤销账号会话、设备和成员访问；轮换 AI 个人空间主密钥。
- 判断文件保护、设备密码和备份加密状态；无法远程抹除的离线副本如实告知。

### 账号删除任务失败

- 保持用户会话撤销和访问阻断，重新运行幂等任务并监控重试。
- 有自有牧场阻塞时指导用户导出、转移或删除，不绕过所有权保护。
- 超过 24 小时目标时主动说明进展和预计措施。

## 六、恢复和复盘

恢复生产前必须满足：根因已修复；旧凭据失效；数据完整性核对；关键 deny 测试
通过；监控无继续异常；用户/主管部门后续动作已安排。

事件结束后五个工作日内形成复盘：时间线、影响范围、根因、控制为何失效、处置
效果、通知/报告、长期整改、负责人和完成日期。相应更新影响评估、政策、测试、
权限和培训材料。事件记录按法律和证明履责所需期限保存，期满删除或匿名化。

## 七、演练

至少每年演练一次“生产密钥泄露 + 跨牧场拒绝 + 用户通知草稿”；每次正式上线前
至少演练账号删除和成员撤权。演练不得使用真实用户凭据或向真实用户发送测试通知。
