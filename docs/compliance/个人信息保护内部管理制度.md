## 一、目标和原则

本制度适用于 eSheep+ App、Supabase 项目、公开网站、邮件、发布后台、备份、
测试环境及为这些系统提供运维的人员。处理活动遵守合法、正当、必要、诚信、
目的明确、最小范围、公开透明、准确完整、期限最短和安全负责原则。

即使当前由一人独立开发和运营，也要把“开发权限”“生产运维”“用户请求”和
“合规复核”作为不同职责留痕，避免凭记忆或临时操作改变生产数据。

## 二、职责

### 个人信息保护负责人

- 维护隐私政策、数据清单、第三方清单、影响评估和自查表。
- 审批 Production 数据结构、权限、服务商和保留周期变更。
- 接收并验证用户权利请求，记录受理、处理、回复和拒绝理由。
- 组织安全事件处置、依法报告/通知和复盘。
- 确认每次 App Store 提交的隐私问卷与实际功能一致。

### 开发与运维职责

- 不在代码、Issue、聊天、截图、测试夹具和日志中写入真实密码、service role key、
  用户 API Key 或不必要的生产个人信息。
- 生产变更通过可审查迁移和配置清单实施；数据库只向前修复。
- 读取生产数据必须有具体故障单或用户请求，限定账号/牧场、时间和字段，并记录
  原因；不得为了“看看数据”进行全库导出。
- 测试优先使用合成数据；必须使用真实数据时先去标识并限制副本期限。

## 三、信息分类

| 级别 | 例子 | 控制要求 |
| --- | --- | --- |
| 高 | 密码/会话、API Key、恢复码、精确位置、未公开照片/语音、完整牧场备份、service role key | 钥匙串/密钥服务、传输加密、最小权限、禁止日志、敏感操作二次确认 |
| 中 | 邮箱、显示名、设备 ID、成员关系、业务记录、AI 对话密文、操作历史 | 账号/牧场隔离、RLS、访问留痕、期限控制、导出保护 |
| 低 | 去标识统计、公开帮助文本、无用户内容的版本信息 | 仍需防止与其他数据重新关联 |

动物业务记录通常不是人的敏感个人信息，但与账号、人员备注、精确位置结合后仍
可能识别自然人，按中等级别管理。

## 四、访问控制和密钥

- Supabase Dashboard 生产组织启用 MFA，至少两名可信 Owner 以避免单点失联；
  日常账号使用最低可用角色。
- 客户端只使用可公开的 publishable key；service role key、数据库密码、SMTP
  凭据和删除 Worker Secret 只放服务端 Secret 管理，不进入 App、仓库或网页。
- 暴露 schema 的表必须同时配置 grants、RLS 和按操作拆分的策略；新增表没有
  allow/deny 测试不得部署。
- Storage 按私有 bucket、对象路径和成员角色授权；禁止把牧场照片改成公开 bucket。
- 设备撤销、成员撤权和账号删除后立即使后续云访问失效；离线既有副本的限制要
  明示给用户。
- 每季度检查 Owner、API Key、Secrets、回调 URL、邮件配置和异常账号；人员或
  服务商变更时立即轮换相应凭据。

## 五、开发和变更流程

每个涉及数据的功能在合并/发布前回答：

1. 新增或改变了哪些个人信息、来源、目的、方式、范围和期限？
2. 能否完全在本机处理，能否减少精度、字段、频率或保留时间？
3. 是否新增第三方、境外地点、SDK、日志、自动化决策或敏感信息？
4. 是否需要更新政策、即时说明、单独同意、影响评估、Privacy Manifest 和
   App Store 问卷？
5. 删除、撤回同意、拒绝权限、跨账号/跨牧场和网络中断是否有测试？

实质变化先完成评估和文本更新，再启用功能；不得先收集、后补政策。

## 六、数据保留与删除

- 活动数据按《个人信息与权限清单》执行；无法说明目的和期限的数据不应保留。
- Production 可配置日志和备份原则上不超过 30 日，具体周期留存控制台证据。
- 用户删除活动照片、AI 会话或账号后，先从活动系统和访问路径移除；备份在循环
  周期内覆盖。依法必须保留的材料隔离保存，不再用于原业务。
- 牧场操作历史需要维持多人业务完整性时，账号删除后将个人 actor 标识置空或
  去标识；不能以“历史需要”为由保留邮箱、设备、会话或头像。
- 临时录音、导入文件、导出文件和渲染缓存任务结束后及时删除；本机清理功能不
  得误删未同步的权威业务数据。

## 七、个人权利请求

支持知情、决定、限制/拒绝、查阅、复制、更正、补充、删除、注销账号、撤回
同意、解释处理规则和投诉。流程：

1. 通过 App 内功能或 `{{PRIVACY_EMAIL}}` 收件并登记时间、请求类型和范围。
2. 只收集足以验证账号控制权的信息；优先要求用户在已登录 App 内确认，不索要
   身份证照片等过度材料。
3. 一般请求在 15 个工作日内完成或说明进展；法律另有更短要求的从其规定。
4. 查阅/复制采用通用可读导出；更正后同步相关活动系统。
5. 拒绝时说明事实和法律理由，并告知申诉/投诉路径。
6. 记录不得包含多余正文；权利请求记录保留三年用于证明履责，期满删除或匿名化。

撤回 AI 同意后停止新的 MiMo 发送并提供删除本地历史的路径；撤回核心出境同意
可能导致云账号/云牧场不可继续使用，应先允许用户导出或处理自有牧场。

## 八、第三方管理

- 选择服务商前核对主体、隐私政策、DPA、子处理者、区域、保留、删除、安全事件
  通知和用户权利协助。
- 在合同/在线条款允许范围内约定目的、期限、方式、种类、保护措施和双方权利义务。
- 每季度查看 Supabase 与 MiMo 更新；SMTP、日志导出、分析 SDK 等新增接收方必须
  先通过影响评估。
- 受托关系结束后确认返还/删除；重大违规或无法说明数据位置时暂停传输。

## 九、培训、检查和审计

- 至少每年完成一次个人信息保护与安全操作自学/复核，并记录日期、材料和结论。
- 每季度执行本目录 README 的检查项目。
- 至少每五年完成一次小型处理者合规审计；发生重大处理变化、安全事件、监管
  要求或处理人数接近 10 万时立即提前审计。
- 自查、影响评估、测试、配置截图和整改证据集中保存，禁止只在聊天中口头确认。

## 十、违规责任

发现越权读取、密钥暴露、隐私问卷虚假、未告知新增收集或未按期处理权利请求时，
立即停止相关处理并启动事件预案。因故意或重大过失违反本制度的人员，应撤销
权限并承担相应内部和法律责任。
